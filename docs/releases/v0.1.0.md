# Art Skill v0.1.0

First public release of Art Skill: reusable art direction for raster artwork and visual asset packs with Codex, Claude Code or Cursor.

## Included

- **34 recipes** across core, additional, optical/material and dream/glow collections, each with concrete review checks and practical limits.
- **52 reviewed examples** made from four original repository photographs, with prompts, source/recipe/output hashes, native dimensions and review notes.
- Eight actions: `help`, `styles`, `brief`, `make`, `pack`, `remix`, `inspect` and `export`.
- A standard-library offline planner with shared-anchor and call-budget checks.
- Project-local installers for all three hosts, with overwrite protection and rollback for failed or interrupted copies.
- Usage-first documentation, collapsed galleries, troubleshooting, contribution guidance and a visible roadmap.

## Downloads and installation

- `art-skill-v0.1.0.zip`: the installable `art-skill/` folder, including all recipes, references, planner, UI metadata, license and version.
- `SHA256SUMS.txt`: the SHA-256 checksum for that ZIP.
- GitHub's source ZIP and tarball: the full repository, including the example galleries and project installer.

For Codex, send this in agent chat:

```text
$skill-installer install the art-skill skill from https://github.com/notEhEnG/art-skill/tree/v0.1.0/skills/art-skill
```

For manual project installation, extract the installable ZIP and copy its `art-skill/` folder into `.agents/skills/` for Codex, `.claude/skills/` for Claude Code, or `.cursor/skills/` for Cursor. Existing installations should be preserved or backed up before replacement.

The installable ZIP excludes the gallery to keep the skill download small. [Browse the gallery](../../README.md#gallery) or use the full source archive for all examples.

## Verification

- Four CI configurations run the 14 helper contract tests: Windows and Linux, each with Python 3.10 and 3.14.
- The release archive is checked for file integrity, complete recipe coverage and successful offline planning after extraction.
- Artwork and source-photo hashes are recorded in the gallery manifests. This release does not regenerate images.

## Known issues

- **Scene-specific recipe prompts:** all 12 additional recipes retain composition instructions from their example photographs. The planner passes those instructions into prompts even for an unrelated product subject. This is a confirmed prompt-construction issue; a resulting image failure was not measured.
- **Portrait conflicts:** 18 recipes include `real people` in their avoidance lists, which can conflict with requested portraits.
- **Documentation synchronization:** the README and catalog are maintained separately; the shipped tests do not check their synchronization.
- **Photo provenance:** the four original photographs have no supplied author/license metadata establishing redistribution permission. Existing collection documentation records this uncertainty; no permission claim is made.

The 14 passing helper tests do not establish that these recipe-content and provenance issues are resolved.

## Known gaps

- Interactive discovery and live image execution still need smoke tests in each host/version.
- A same-style multi-asset pack, actual cutout transparency and cross-host ZIP/export behavior remain pending.
- Image generation requires an available host image tool. The package does not provide a backend or silently enable a paid API.
- Installation rollback handles errors and interruptions; forced process termination or power loss can leave partial files. Cleanup failures are reported.

See the [validation record](../validation.md), [roadmap](../../README.md#known-gaps-and-roadmap) and [changelog](../../CHANGELOG.md).
